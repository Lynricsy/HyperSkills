- https://diataxis.fr (CC-BY-SA-4.0) — https://diataxis.fr — The four document types and the compass that decides between them from two questions about the reader (does the content inform action or cognition; does it serve acquisition or application of skill). - mattpocock/skills (MIT) — https://github.com/mattpocock/skills @ 3cca18b368ae95cdbdebbff572ccafa662551015 — paths: .agents/writing-docs.md, skills/productivity/teach — The defining constraint - the one sentence stating what makes this thing behave differently from the obvious default - together with the instruction to write it as plain prose rather than as a labelled aside, because the label reads as filler. The rule that a self-check item must be checkable by the reader without opening the source document. Hunting real reader questions (support threads, issues filed twice, the changelog's own renames) instead of inventing them, and keeping the count honest to what the hunt found rather than padding a thin page to match a rich one. Branches presented as a table or list rather than a paragraph the reader must read in full. Not naming the author of a claim, so the claim stands or falls on its own.
- google/styleguide (CC-BY-3.0) — https://github.com/google/styleguide @ 3b8822983dc779c498961cc86332a28c07590f64 — paths: docguide/READMEs.md, docguide/best_practices.md, docguide/style.md — README placement and minimum content: the README belongs at the top level of the code it describes rather than inside the documentation directory, every top-level directory of a shipped package has one, and it must contain or point to what the package is for, its points of contact, its status when that status is deprecated or not for general release, how to use it with copyable commands, and links onward. Also the principle that documentation degrades more slowly the closer it lives to the code it describes, which is the argument for auditing docs in the same change as the code.
